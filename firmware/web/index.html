GhostHID

connecting… USB ?
The target is not receiving input. GhostHID is on the network, but the computer it is plugged into has not enumerated it over USB — unplugged, asleep, or a charge-only port.

Access point

Access

Passwords are write-only: the device reports whether one is set, never its value. Leave a field blank to keep the current one. Changes take effect after a reboot.

Connection

Endpoint

One WebSocket carries everything. JSON text frames, one message per frame. 

ws://<device>/ws

Only one controller may connect at a time; a second gets close code 1013. Two controllers sharing one held-key state would fight over it.

1 · Authenticate first

{"type":"auth","token":"ghosthid"}
→ {"type":"auth","ok":true,"version":"…","usb":true}

Every other command except auth is rejected until this succeeds. usb tells you whether the target has actually enumerated the device — if it is false, input goes nowhere.

2 · Keep the link alive

{"type":"ping"}   → {"type":"pong","usb":true}
{"type":"status"} → {"type":"status","version":"…","usb":true,"held":0}

Ping at least every 250 ms. If input is held and nothing arrives for 750 ms, the device releases everything — the backstop for a controller that vanishes without closing the socket.

3 · Input

MessageNotes
{"type":"key","key":"a","pressed":true} A single character, or a name: CTRL SHIFT ALT GUI ENTER ESC TAB BACKSPACE DELETE INSERT HOME END PAGEUP PAGEDOWN UP DOWN LEFT RIGHT CAPSLOCK F1–F12. Aliases: WIN CMD META SUPER → GUI, CONTROL → CTRL, RETURN → ENTER. Case-insensitive.
{"type":"text","text":"hello"} ASCII / US layout. Non-ASCII bytes are skipped rather than typed as garbage.
{"type":"mouse_move","dx":12,"dy":-4} Relative. Any integer — the firmware splits values beyond ±127 across multiple HID reports.
{"type":"mouse_button","button":"left","pressed":true} left, right or middle.
{"type":"mouse_wheel","delta":-1,"pan":0} delta scrolls (positive = up), pan is the horizontal wheel.
{"type":"release_all"} Release every held key and button. Cheap and idempotent — send it whenever your UI loses focus.

Input commands are fire-and-forget: no reply on success. A reply means something went wrong.

4 · Configuration

{"type":"get_config"}
→ {"type":"config","sta_ssid":"…","sta_pass_set":true,
   "ap_pass_set":true,"token_set":true,"name":"ghosthid"}

{"type":"set_config","sta_ssid":"MyNet","sta_pass":"…",
 "ap_pass":"…","token":"…","name":"ghosthid"}
→ {"type":"config_saved","reboot_required":true}

{"type":"reboot"} → {"type":"rebooting"}

Every field of set_config is optional; omitted fields keep their stored value. Secrets are write-only — get_config reports only whether each is set. Settings persist in NVS and survive reflashing.

Minimal client

import json
from websockets.sync.client import connect

with connect("ws://192.168.4.1/ws") as ws:
    ws.send(json.dumps({"type":"auth","token":"ghosthid"}))
    ws.recv()
    ws.send(json.dumps({"type":"text","text":"hello world"}))
    ws.send(json.dumps({"type":"key","key":"ENTER","pressed":True}))
    ws.send(json.dumps({"type":"key","key":"ENTER","pressed":False}))
