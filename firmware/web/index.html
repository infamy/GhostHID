GhostHID
THE KEYBOARD THAT ISN'T THERE

GhostHID is a wireless USB keyboard and mouse. The small board it runs on plugs into a computer's USB port and that computer sees an ordinary keyboard and mouse — no drivers, no agent, no account, and no network connection on its end. Everything you type or click on this page is delivered over Wi-Fi to the board, which types it for you.

Because the target needs nothing installed, it works on machines you cannot install software on. The trade-off is that GhostHID is input-only: it cannot see the target's screen, read its clipboard, or know where its pointer is — which is why absolute pointer mode exists.

Safety

A key left stuck down on the target is the worst thing this device can do, so three independent things prevent it: everything is released the moment this page disconnects; if the page stops responding for 750 ms while input is held, the device releases it anyway; and the board's BOOT button releases everything with no network involved. Release keys in the top bar does the same on demand.

Project

Open source under the MIT licence. The firmware statically links some LGPL libraries, so a redistributed binary must be accompanied by a pointer to its source — see THIRD-PARTY-LICENSES.md in the repository. Updates are installed from the Settings tab over Wi-Fi; no cable needed.

Control API

Endpoint

One WebSocket carries everything. JSON text frames, one message per frame. 

ws://<device>/ws

Only one controller may connect at a time; a second gets close code 1013. Two controllers sharing one held-key state would fight over it.

1 · Authenticate first

{"type":"auth","token":"ghosthid"}
→ {"type":"auth","ok":true,"version":"…","usb":true}

Every other command except auth is rejected until this succeeds. usb tells you whether the target has actually enumerated the device — if it is false, input goes nowhere.

2 · Keep the link alive

{"type":"ping"}   → {"type":"pong","usb":true,"kvm":0,"locks":2,"hled":3}
{"type":"status"} → {"type":"status","version":"…","usb":true,"held":0}

locks is the target's lock-LED bitmap (b0 Num, b1 Caps, b2 Scroll); hled counts the output reports the host has sent — non-zero means the target is actually driving GhostHID's keyboard, not just powering it.

Ping at least every 250 ms. If input is held and nothing arrives for 750 ms, the device releases everything — the backstop for a controller that vanishes without closing the socket.

3 · Input

MessageNotes
{"type":"key","key":"a","pressed":true} A single character, or a name: CTRL SHIFT ALT GUI ENTER ESC TAB BACKSPACE DELETE INSERT HOME END PAGEUP PAGEDOWN UP DOWN LEFT RIGHT CAPSLOCK F1–F12. Aliases: WIN CMD META SUPER → GUI, CONTROL → CTRL, RETURN → ENTER. Case-insensitive.
{"type":"text","text":"hello"} ASCII / US layout. Non-ASCII bytes are skipped rather than typed as garbage.
{"type":"mouse_move","dx":12,"dy":-4} Relative. Any integer — the firmware splits values beyond ±127 across multiple HID reports.
{"type":"mouse_abs","x":0.62,"y":0.31} Absolute. Fractions of the target's desktop, 0..1 — not pixels, because the device cannot learn the target's resolution and a fraction survives a resolution change. Not affected by the target's pointer acceleration, so the pointer lands exactly here and the controller always knows where it is. Values outside 0..1 are clamped.
{"type":"mouse_button","button":"left","pressed":true} left, right or middle.
{"type":"mouse_wheel","delta":-1,"pan":0} delta scrolls (positive = up), pan is the horizontal wheel.
{"type":"media","key":"vol_up"} Consumer-control tap: vol_up vol_down mute play_pause next prev stop bright_up bright_down.
{"type":"system","key":"sleep"} System-control tap: sleep wake power. The host's OS decides whether to honour these.
{"type":"release_all"} Release every held key and button. Cheap and idempotent — send it whenever your UI loses focus.

Input commands are fire-and-forget: no reply on success. A reply means something went wrong.

4 · Configuration

{"type":"get_config"}
→ {"type":"config","sta_ssid":"…","sta_pass_set":true,
   "ap_pass_set":true,"token_set":true,"name":"ghosthid",
   "ap_always":true,"reboot_pending":false}

{"type":"set_config","sta_ssid":"MyNet","sta_pass":"…",
 "ap_pass":"…","token":"…","name":"ghosthid","ap_always":true}
→ {"type":"config_saved","reboot_required":true}

{"type":"reboot"} → {"type":"rebooting"}

Every field of set_config is optional; omitted fields keep their stored value. Secrets are write-only — get_config reports only whether each is set. Settings persist in NVS and survive reflashing.

reboot_required and reboot_pending are facts, not guesses: Wi-Fi, access-point and device-name changes are only read at startup, while a token change takes effect on the next connection and reports false. ap_always:false drops the access point while a network is joined and restores it if that connection is lost. 

GET /api/export   (header X-GhostHID-Token: <token>)
→ {"ghosthid_export":1,"name":"…","kvm_host":"…","kvm_ca":"…", …}

Downloads the board's non-secret settings — including the server certificate — as JSON, for provisioning another board. Feed it back through set_config (this is what the web UI's Import button does). Passwords and the token are never included.

5 · Firmware update

POST /api/ota?token=<token>
Content-Type: application/octet-stream
Body: raw firmware.bin

→ {"type":"ota_ok","rebooting":true}
→ {"type":"error","error":"not an ESP32 app image …"}   (400)
→ {"type":"error","error":"unauthorized"}               (401)

Content-Type: application/octet-stream is required. Without it curl defaults to x-www-form-urlencoded, and the server tries to parse the whole image as form fields and runs out of memory — the upload dies with a reset connection rather than an error. The token may also be sent as an X-GhostHID-Token header. Upload firmware.bin, not ghosthid-merged.bin. HID input is locked out for the duration. Writes go to the inactive OTA slot, so an interrupted upload cannot brick the device. 

curl -sS -H "Content-Type: application/octet-stream" \
  --data-binary @firmware.bin \
  "http://<device>/api/ota?token=<token>"

Minimal client

import json
from websockets.sync.client import connect

with connect("ws://192.168.4.1/ws") as ws:
    ws.send(json.dumps({"type":"auth","token":"ghosthid"}))
    ws.recv()
    ws.send(json.dumps({"type":"text","text":"hello world"}))
    ws.send(json.dumps({"type":"key","key":"ENTER","pressed":True}))
    ws.send(json.dumps({"type":"key","key":"ENTER","pressed":False}))
